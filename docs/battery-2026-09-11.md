## Block 8 — hue motion. **Void. Re-run it.**

### The controls both failed

- **Catch: 1 false positive of 1.** Shown the same rotation twice and asked which he preferred, he
  answered "b" decisively in 1297ms. That is the tie-breaking habit, and it is the habit the whole
  mirrored-repeat design exists to detect.
- **Anchor: missed.** A rotation was played against a colour that does not move at all, and he
  named the *moving* one as steadier — in 835ms, which reads as confident rather than inattentive.

The anchor miss is worth more than "he stopped watching", because he plainly had not: his response
times through the block are 1-4s and his block 7 anchor, eight minutes earlier, was correct. The
likely cause is the question. Block 8's anchor asks **"which one was steadier?"** while every trial
around it asks about *pulsing* or about *preference*. Answering "the one that moved" is the right
answer to the question he had in his head. Block 7's anchor uses the same wording and sits in a
block where every trial asks that same question, and it was answered correctly. **Block 8's anchor
needs to be phrased in the block's own vocabulary**, not inherited from block 7.

### The preference answers are confounded with position

| order played | answer |
|---|---|
| raw first, flattened second | **"b"** (flattened) |
| flattened first, raw second | "can't tell" |
| raw first, flattened second (repeat) | **"b"** (flattened) |
| flattened first, raw second (repeat) | "can't tell" |

He was decisive exactly when the answer was "b" and unsure exactly when it was not. That is the
same shape as the catch false positive. `orderRobustness` is **null** here — not low, *null* — because
no pair was answered decisively in both orders, so the block's own credibility instrument has
nothing to report.

**Note a gap in the gate this exposes:** `PreferenceReading.trustworthy` returns `true` for these
four trials, because a null `orderRobustness` defaults to passing and the catch is read separately by
`controls()`. Neither number is wrong on its own, but "trustworthy" on its own is misleading on a
block like this one. Read `controls()` alongside it, or do not read either.

### The visibility question was never recorded readably

`hueMotionTrials` drew the interval order inside the `intervals` list and then wrote the arms as a
**constant** pair — `armFirst = ARM_RAW, armSecond = ARM_FLAT` — whichever way the trial actually
played. The answers name an interval letter and nothing else, so with the recorded arm order
dishonest there is no route back to which arm he pointed at. His three answers were "a", "b", "a",
and **none of them can be attributed to the raw or the flattened sweep**.

They are not recoverable after the fact either: the result file stores `(config, answers)` and the
seed lives only in the progress file, which is deleted when a block completes. The replay that
rebuilds state needs the seed, and it is gone.

Fixed, with the order drawn once and both the intervals and the meta derived from it.
`LabBlocksTest` now pins the invariant generally rather than for this block: **within one block,
kind and scope, an arm id must always name the same stimulus.** The check is scoped by
`anchorLevel`/`toLevel`/`clip` exactly as `LabAnalysis.PairKey` is, because block 4's arms are ease
durations that legitimately run at two anchors. Verified to fail on the original code before being
kept.

### What a re-run needs

1. The arm-order fix (done).
2. **The anchor asked in block 8's own words.** "Which one was steadier?" is the wrong question in a
   block about pulsing and colour motion.
3. **Something that separates his tie-breaking habit from a preference on the `prefer` question.**
   The mirrored repeat is already there and it did its job — it detected the habit rather than
   hiding it. What it cannot do is produce an answer anyway. Worth considering whether the
   preference question is even askable before `pump` establishes that the swing is visible at all.

**Nothing about the hue premise is in doubt.** The measured 2x swing (`HuePathAnalysis`, raw 2.00x
vs flattened 1.01x, means equal to within 2%) is arithmetic over `StripResponse` and does not depend
on this sitting. What is unknown is still exactly what it was before: whether he can see it, and
whether he wants it gone.
